# V1.1 — Organization-Scoped Data

## Problem

Any authenticated user can see all data. There's no workspace isolation — if Jelo signs up, he sees Noel's creatives and vice versa. We need organization-scoped data so teams share a workspace, but random signups can't see anything.

## How It Works

Better Auth's organization plugin is already installed. The auth schema has `organization`, `member`, `invitation` tables and `session.activeOrganizationId`. We just need to wire it into the data layer and UI.

## Changes

### 1. Schema — Add `organizationId` to all data tables

Add to each table:
```ts
organizationId: text("organization_id")
  .notNull()
  .references(() => organization.id, { onDelete: "cascade" }),
```

Tables affected:
- `ad_creative`
- `landing_page`
- `landing_page_version`
- `campaign_config`
- `ad_set`
- `performance_log`

Add index on `organizationId` for each table.

Migration: existing data gets assigned to the first org created, or we wipe dev data.

### 2. tRPC — Org-scoped middleware

Update `protectedProcedure` in `src/lib/trpc/init.ts`:

```ts
export const protectedProcedure = t.procedure.use(({ ctx, next }) => {
  if (!ctx.session) throw new TRPCError({ code: "UNAUTHORIZED" });

  const orgId = ctx.session.session.activeOrganizationId;
  if (!orgId) throw new TRPCError({ code: "FORBIDDEN", message: "No active organization" });

  return next({
    ctx: {
      session: ctx.session as Session,
      organizationId: orgId,
    },
  });
});
```

All routers use `ctx.organizationId` to:
- **Create**: set `organizationId` on insert
- **Read**: filter by `organizationId` in all queries
- **Update/Delete**: verify item belongs to `organizationId` before mutating

### 3. Org setup flow — Post-signup redirect

New page: `src/app/(auth)/setup-org/page.tsx`

Flow:
1. User signs up → lands on setup page
2. Options: "Create a workspace" or "Join via invitation"
3. Create: enter org name → `organization.create({ name, slug })` → set as active → redirect to dashboard
4. Join: enter invite code or check pending invitations → accept → redirect

The dashboard layout checks `session.activeOrganizationId`. If null, redirect to `/setup-org`.

### 4. Org switcher — Sidebar

Add to `AppSidebar` footer (above user name):
- Shows current org name
- Dropdown to switch between orgs the user belongs to
- Uses `organization.setActive({ organizationId })` from Better Auth client
- "Create new workspace" option at bottom

### 5. Invite flow — Settings page

New page: `src/app/(dashboard)/settings/page.tsx`

Sections:
- **Members** — list current org members (name, email, role)
- **Invite** — email input + role select (admin/member) → `organization.inviteMember({ email, role })`
- **Pending invitations** — list with revoke option

Only org admins (role = "owner" or "admin") can invite/remove members.

### 6. Better Auth client helpers

Already exported from `src/lib/auth-client.ts`:
```ts
organization.create({ name, slug })
organization.setActive({ organizationId })
organization.inviteMember({ email, role, organizationId })
organization.removeMember({ memberIdOrEmail })
organization.getFullOrganization()
organization.listOrganizations()
```

## Auth Client API Reference

```ts
// Create org
const org = await organization.create({ name: "Reviv", slug: "reviv" });

// Set active org on session
await organization.setActive({ organizationId: org.id });

// List user's orgs
const orgs = await organization.listOrganizations();

// Invite member
await organization.inviteMember({
  email: "jelo@reviv.com",
  role: "member", // "owner" | "admin" | "member"
  organizationId: org.id,
});

// Accept invitation
await organization.acceptInvitation({ invitationId });

// Remove member
await organization.removeMember({ memberIdOrEmail: "jelo@reviv.com" });

// Get current org with members
const full = await organization.getFullOrganization();
```

## Roles

| Role | Can view data | Can edit data | Can invite | Can manage org |
|------|--------------|--------------|-----------|---------------|
| member | Yes | Yes | No | No |
| admin | Yes | Yes | Yes | No |
| owner | Yes | Yes | Yes | Yes |

For V1.1, all members can edit. Role-based field restrictions can come later.
